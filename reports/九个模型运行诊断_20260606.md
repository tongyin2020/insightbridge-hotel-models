## 真实 bug

### 1. System 1 的 DirectorAI 运行器参数已经和底层引擎脱节

- 文件：`system1_chatgpt_harness/run_21d_harness.py`
- 位置：`run_director()` 内部把 `objective_mode` 传给 `recommend(...)`
- 实际错误：
  - `TypeError: recommend() got an unexpected keyword argument 'objective_mode'`
- 原因：
  - 运行器调用的是三参数形式
  - 底层 `recommend()` 现在只接受 `data, hotel_settings=None`

### 2. System 2 默认运行路径缺少 `app` 包路径

- 文件：`system2_claude_simulation/run_simulation.py`
- 问题表现：
  - MARE 首次执行时报错 `ModuleNotFoundError: No module named 'app'`
- 触发点：
  - `system2_claude_simulation/pricing_engine.py` 内部使用
  - `from app.services.bundle_engine import generate_bundle_offers`
- 原因：
  - `run_simulation.py` 只把 `system2_claude_simulation` 自己加入了 `sys.path`
  - 没有把 `system1_chatgpt_harness/mare_engine/api` 加进去

### 3. System 3 复用了 System 2 的定价引擎，但同样没有补 `app` 包路径

- 文件：`system3_crewai/main.py`
- 问题表现：
  - 首次执行 MARE 时同样报 `ModuleNotFoundError: No module named 'app'`
- 原因：
  - `main.py` 加入了 `system2_claude_simulation` 路径
  - 但没有加入 `system1_chatgpt_harness/mare_engine/api`

## 本次环境里触发的限制

这些不一定是代码 bug，但会影响你现在在这台环境里的运行结果：

### 1. Playwright/Chromium 启动失败

- 现象：
  - Booking.com 抓取阶段多次报错
  - Chromium 启动后触发 `Permission denied (1100)` / `SIGTRAP`
- 影响：
  - 实时 Booking 抓取降级
  - 模型会改走 fallback 数据

### 2. Firecrawl 实时信号没有拿到真实值

- 现象：
  - 本次检查里看到 `0/5因子真实`
- 影响：
  - System 3 这次实际走的是 simulated / fallback 信号

### 3. AgentOps 在无网络环境下持续重试上传

- 现象：
  - 日志里反复出现 `Failed to resolve 'api.agentops.ai'`
- 影响：
  - 增加日志噪音
  - 可能拖慢启动和退出

## 优先级建议

1. 先修 System 1 `run_director()` 的接口签名问题，否则这一套系统始终有 1 个模型直接挂掉。
2. 再统一修 System 2 / System 3 的 Python 路径初始化，把 `app` 依赖路径补齐。
3. 最后再处理 Playwright、Firecrawl、AgentOps 的环境降级逻辑，减少无网或受限环境下的误报。
