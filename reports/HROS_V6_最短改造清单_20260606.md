# HROS V6 最短改造清单

日期：2026-06-06

目标：让当前九个模型尽快接近文档中 `Definition of Done`

文档目标字段：

- `recommended_price`
- `predicted_occupancy`
- `predicted_revpar`
- `expected_revenue_lift`
- `price_risk_score`
- `opportunity_score`
- `rate_confidence`
- `attribution`
- `hotel_profile_version`

## 优先级顺序

### P0. 统一单条输出 schema

先定义一套统一输出规范，至少区分三类模型：

- MARE 输出 schema
- DirectorAI 输出 schema
- SelfACQ 输出 schema

原因：

- 现在三个系统都能跑，但字段风格不统一
- 不先统一 schema，后面所有 V6 收口都会变成补丁式开发

建议位置：

- `共用_HROS_V6引擎/hros_v6/schemas_v6.py`

建议动作：

- 增加 `DirectorResultV6`
- 增加 `SelfACQResultV6`
- 明确 `attribution` 的统一字段名，不要一处叫 `revenue_attribution`，一处只写入日志表

## P1. 给 DirectorAI 和 SelfACQ 补齐 V6 公共字段

### 1. DirectorAI

当前状态：

- 已有：`crm_adjusted_price`, `integration_score`, `crm_v6_guardrail`
- 缺少：`predicted_occupancy`, `predicted_revpar`, `price_risk_score`, `opportunity_score`, `rate_confidence`, `attribution`, `hotel_profile_version`

最短做法：

- 把 `crm_adjusted_price` 映射成该模型的 `recommended_price`
- 用现有 `elasticity_revpar` 推导 `predicted_revpar`
- 补一个轻量 adapter，把 CRM 输出包装成统一 V6 结果结构
- `attribution` 至少先写简化版：CRM 增量价值 + baseline 对比

主要修改点：

- `system2_claude_simulation/run_simulation.py`
- `system3_crewai/main.py`
- `system1_chatgpt_harness/run_21d_harness.py`

### 2. SelfACQ

当前状态：

- 已有：`direct_offer_price`, `predicted_occupancy`, `revpar_lift_vs_market`, `selfacq_v6_direct_ltv`, `hotel_profile_version`
- 缺少：`predicted_revpar`, `price_risk_score`, `opportunity_score`, `rate_confidence`, `attribution`

最短做法：

- 把 `direct_offer_price` 映射成该模型统一的 `recommended_price`
- 用现有市场锚价和 `predicted_occupancy` 计算 `predicted_revpar`
- 给 SelfACQ 加一个小型 V6 adapter，补 `risk/opportunity/confidence`
- 用 `SelfACQEngineV6` 的 `direct_advantage` 作为 attribution 基础

主要修改点：

- `system2_claude_simulation/run_simulation.py`
- `system3_crewai/main.py`
- `system1_chatgpt_harness/run_21d_harness.py`

## P1. 把 attribution 从“系统级日志”提升到“单条结果字段”

当前状态：

- System 2 有系统级 `attribution_log`
- 单条 MARE/CRM/SelfACQ 结果里没有稳定挂 `revenue_attribution`
- System 3 基本没有等价的归因落库
- System 1 几乎没有这层

最短做法：

- 每次生成模型结果后，把 `RevenueAttributionEngine().attribute(...)` 的结果直接挂进 `result["revenue_attribution"]`
- 先允许 CRM / SelfACQ 用简化 attribution，再逐步细化

主要修改点：

- `system2_claude_simulation/run_simulation.py`
- `system3_crewai/main.py`
- `system1_chatgpt_harness/run_21d_harness.py`

## P1. 给 System 1 的 MARE 补上真正的 V6 adapter

当前状态：

- System 1 MARE 现在主要有 `recommended_price` 和基础弹性结果
- 还没像 System 2 / 3 那样稳定挂出 `price_risk_score`, `opportunity_score`, `rate_confidence`, `hotel_profile_version`

最短做法：

- 在 `run_21d_harness.py` 的 MARE 分支里，像 System 2 一样接 `apply_v6_to_mare_output`

主要修改点：

- `system1_chatgpt_harness/run_21d_harness.py`

## P2. 给 System 3 补全收益归因落库

当前状态：

- System 3 已有 demand-state audit
- 但没有看到与 System 2 等价的 attribution 表写入逻辑

最短做法：

- 复用 System 2 的 attribution 计算逻辑
- 增加 `attribution_log` 表或在现有表里新增归因 JSON 字段

主要修改点：

- `system3_crewai/main.py`

## P2. 修正共享 V6 测试断言

当前状态：

- `tests/test_hros_v6.py` 和 `tests/test_hros_v6_bugfix.py` 共 `18` 通过，`1` 失败
- 失败原因：本地实现将配置错误 sentinel 改成了 `999.0`，测试还在断言 `100.0`

最短做法：

- 统一规范：到底 sentinel 应该是 `100.0` 还是 `999.0`
- 代码和测试二选一同步

主要修改点：

- `共用_HROS_V6引擎/hros_v6/revenue_decision_layer_v6.py`
- `共用_HROS_V6引擎/tests/test_hros_v6_bugfix.py`

## 推荐实施顺序

1. 先统一 schema
2. 给 System 1 MARE 补 V6 adapter
3. 给 DirectorAI 做 V6 result adapter
4. 给 SelfACQ 做 V6 result adapter
5. 把 attribution 下沉到单条结果
6. 给 System 3 补 attribution 落库
7. 修共享测试断言

## 最终判断

如果只想“尽快接近文档验收标准”，最短路径不是重写模型，而是：

- 统一输出格式
- 把现有 V6 能力从系统级、日志级，推进到单条结果级
- 补齐 System 1 和 System 3 的接入深度
